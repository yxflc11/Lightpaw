# Lightpaw 4.4.0 · 行为与边界

Lightpaw 把本机 Mole 的常用操作与 Codex 内存观察放进原生 SwiftUI / AppKit 界面。日常操作不需要打开 Terminal；这是本地自用工具，并非 Mole 或 OpenAI 的官方客户端。

v4.4 将「Codex → 后台工具…」改为逐项开关，支持规范自定义 MCP 和经本机 Codex CLI、安装目录及清单核验的普通 MCP 插件。提供“全部 / 可管理”筛选，开启、关闭、待应用和受保护状态分开显示。内置共享工具与来源未核实服务仅显示用途和占用；未关联的实例和占用显示 `—`。

开关保存的是后续加载意图，不即时断开连接或释放内存。Lightpaw 保持运行时，沿用每 10 秒采样检查；连续两次确认本机 Codex 主程序及命令行引擎均退出且至少间隔 2 秒，才尝试应用。写入前再次检查进程状态、配置身份及 SHA-256，并保留私有备份。没有配置热重载、自动退出 Codex、SIGTERM 或按 Node 名称批量结束。可随时撤销待办；配置被其他操作改变时暂停，需重新核对确认。纯技能插件不列作后台服务，其他配置层控制的插件不提供开关。

待办存在 Lightpaw 自身偏好中，只包含工具标识、基准与目标开关、配置指纹及待办状态；不保存密钥、命令或环境。退出 Lightpaw 后暂停处理，再打开继续；待办不能代替实际生效状态。当前原子编辑器只支持可明确解释的单行 TOML，复杂语法保守拒绝，不覆盖其他配置。

后台采样每 10 秒运行一次，临时 Foundation 对象在每次采样结束后释放。小猫四帧缓存与不可见暂停保持不变；Mole 完整状态仅在总览或面板可见时采集。无待办时不额外检查进程或插件；插件清单只在打开、刷新、操作插件和确认退出后的待办处理中读取，没有新增计时器或常驻服务。

建议安装入口：`~/Applications/Lightpaw.app`，当前版本 **4.4.0（build 25）**；构建产物为 `dist/Lightpaw.app`。应用更名后继续使用 bundle ID `local.codex.memorywatch`、主可执行文件 `CodexMemoryWatch` 和原有日志、操作历史目录，保持现有记录连续。

关闭窗口不会退出：Codex 监测继续运行，已开始的维护任务也不会因关闭窗口自动取消。点击菜单栏小猫打开状态面板，再点“打开 Lightpaw”可恢复窗口；重新打开应用也可恢复。右键小猫或应用菜单中的“退出 Lightpaw”、`⌘Q` 才会退出。任务运行中退出会先询问是否取消本次操作。

## 五项导航与更多

侧栏依次为“总览、清理、应用、Codex、磁盘”。“更多”以与导航同字号、同行高的整行按钮收纳系统维护和操作历史，七项能力均保留。清理入口统一使用刷子图标。

| 入口 | 当前功能 |
| --- | --- |
| 总览 | 显示 Mole 的真实健康评分、CPU、系统内存、磁盘和电池状态，以及 Codex 迷你趋势。缺失值显示为未知或 `—`。 |
| 清理 | 扫描候选，搜索、逐项勾选，再检查并移到废纸篓；“更多清理选项”提供当前过滤范围全选、永久模式、保护规则与完整扫描结果。 |
| 应用 | 全部、Homebrew、可更新三个筛选；本机 cask 清单、明确检查更新、逐项核对版本后更新。普通及 Homebrew 卸载先检查清单，复杂卸载单独审阅完整脚本；禁用自动依赖清理。 |
| Codex | 每 10 秒采样内存、系统压力与进程变化，显示最近 60 点趋势和进程表。 |
| 磁盘 | 选择文件夹、进入子目录、返回上级、查看占用及在 Finder 中定位；**只读浏览，不提供删除按钮**。部分扫描标为下限，目录占用不等于可释放空间。 |
| 更多 → 系统维护 | 先预览，再确认执行适用的缓存、数据库、索引、网络等维护步骤；完整输出保留供核对。 |
| 更多 → 操作历史 | 合并 Lightpaw 与 Mole 最近 20 次记录；缺少结束标记或旧日志归属不明确时，不能据此认定操作完整成功。 |

主窗口采用约 900 × 640 pt 的紧凑深色布局、灰白文字与淡紫强调色。页头采用选定的 F 字形猫，只做低频眨眼和摆尾；窗口隐藏、最小化、关闭、完全被遮挡，或系统开启“减少动态效果”时静止。它不参与监测或清理判断。

## 菜单栏与状态口径

菜单栏使用 F 字形猫的小尺寸模板，单击打开 **320 pt 宽、自适应高度的原生弹窗**，展示 Mole 健康评分、可用空间、内存压力和 Codex 内存。可即时刷新、点击指标进入详情、在面板内启动或取消只读清理扫描。完成后进入清理页逐项选择，仍需核对确认；失效结果会提示重新扫描。评分说明在面板内展开。应用位于前台时，可用 `⌘⇧S`（Cmd–Shift–S）或“显示状态面板”菜单打开；这不是系统全局热键。点击弹窗外部、切换应用、按 Escape 或进入主窗口可收起，右键小猫可打开主窗口或退出。

健康分数直接来自 Mole 的 `health_score`，Lightpaw 不另算分数，也不编造逐项扣分。仅接受 0–100 的整数；缺失、布尔值、非整数或越界值显示为 `—` / 暂不可用。总览可打开评分说明，查看 Mole 的原始说明。评分只是概览，不能替代内存压力或故障诊断。压力为警告或严重时，总览与面板优先显示该警告，原始分数不变。

总览可见或状态弹窗打开时，约每 30 秒采集一次 Mole 状态；维护任务进行中不启动新的周期采集。两处都不可见时暂停该周期采集，Codex 的 10 秒监测继续。超过 60 秒的系统数据保留数值但标明“旧数据”或“已过期”，评分改为灰色；重新打开可见界面会按需更新。更新失败不会把旧值冒充本次结果，也不会把未知值变成 0。

## 预览、确认与范围

清理和系统维护先运行 `--dry-run`，预览完成后才允许点执行按钮。预览有效期为 10 分钟；保护规则变化后需要重新预览。执行前检查版本、时效与规则，确认后再次核对预览时效和保护规则；系统维护还会再次检测 Mole 版本。

清理默认全部不选、默认移到废纸篓。Mole 1.61.0 没有精确选择清理接口，因此仅用其生成候选清单；原生 `SelectedCleanup` 对勾选路径单独操作，不调用整组 `mo clean`，也不清空废纸篓。默认移到废纸篓可取回文件，清空后才释放占用；永久删除必须在“更多清理选项”中显式开启；主按钮随之变为红色“永久删除…”，仍需再次确认。

逐项清理支持明确的用户缓存、日志、常见开发工具缓存及部分 Chromium 缓存内容；模型、凭据、系统服务、当前 Codex / Lightpaw 状态等有额外保护。不可处理的项目收在“已保护 N 项”折叠区，展开后显示锁和原因。主列表仅显示勾选框、名称和大小；重名项补充最短可区分的父路径，完整路径可悬停查看或通过右键“查看项目详情”核对。正在使用、权限不可核实、树过大或读取超时的项目会保留。候选大小沿用 Mole，可能包含上级与下级重叠；选中摘要折叠上级，并不等于实际可释放磁盘空间。

检查在后台绑定文件树身份和保护规则，执行前再次检查。祖先或文件符号链接、被替换的目标、新增内容、变化的保护规则都会阻断。执行计划有效期 5 分钟；父目录内有已知未勾选子项时保留父目录。永久删除采用同父目录临时隔离及描述符相对删除，不跟随符号链接；开始删除一项后，取消在该项结束后停止后续项目。失败时会报告部分删除或恢复位置。废纸篓的文件来源经过隔离目录，取回时请按确认清单的原路径放回。

普通应用卸载沿用 Mole：先验证唯一匹配及 bundle 身份，再在一个确认窗口展示清单并执行。Codex、Lightpaw、系统组件及不明确的同名应用受到保护。个人数据按 Mole 默认规则保留，具体以清单为准。

应用列表与每次卸载前均独立核对 Homebrew 来源，避免自定义安装目录被 Mole 误标为普通应用。Homebrew cask 卸载从已安装的 receipt、配置和配方快照绑定应用路径与 token；确认时复核身份和元数据，运行中的应用需先正常退出。使用 `brew uninstall --cask`，固定 `HOMEBREW_NO_AUTOREMOVE=1`，不用 `--zap` / `--force`，不自动移除依赖。预览列出工件和安装时声明的卸载操作，实际卸载不保证进废纸篓。复杂 Ruby flight hooks 从已安装快照显示完整源码、路径与 SHA256；只有明确勾选脚本审阅后才能执行。预览不运行 Ruby，执行前重新核对源码、已定位的外部程序及应用身份；无法绑定完整源码、工件或目标时继续阻断。Ruby 内部和间接调用无法静态穷举，不能把声明工件当作完整影响清单。Ruby cask 使用已审阅的安装快照绝对路径执行。这不是 Homebrew formula 的包管理器。[Homebrew 环境选项说明](https://docs.brew.sh/Manpage#environment)

Homebrew 列表仅从本机 receipt、配置和安装快照读取，不联网或执行配方。点击“检查更新”才运行 `brew update` 刷新 Homebrew 与配方元数据，然后读取已安装 cask 的更新状态；不会批量升级应用。列表区分可更新、自行更新、固定版本、停用、`latest` 与不支持直接处理的配方。明确版本的单项更新先核对来源、旧版本和目标版本，再执行 `brew upgrade --cask <token>`；禁用自动依赖移除和安装后清理，执行前后再次核对安装记录。检查失败、取消或卸载后旧结果失效。附带额外依赖、复杂安装/升级操作或无法核对的第三方配方暂不直接更新，显示具体原因。

系统维护首次或预览失效时显示“预览维护项目”，预览有效后显示“检查并继续…”，仍按 Mole 整组预览、确认、执行；可能刷新网络、数据库、索引或 Finder 设置，不是释放内存的开关。不会因新版安装而自动执行优化。

“查看保护规则”只读展示 `~/.config/mole/whitelist`、`whitelist_optimize`，后者不存在时读取兼容文件 `whitelist_checks`；不编辑规则。没有自定义文件时使用 Mole 默认策略，Mole 的扫描保护与原生清理额外保护共同限定候选范围。

实际清理与 Mole 写入仅支持已核对的 **Mole `1.61.0`**，固定使用 `/opt/homebrew/bin/mo`。版本不符或未检测到时暂停维护写入，普通应用卸载准备也会被限制；只读预览仍有入口，Homebrew 使用单独核对的接口。不会自动安装、升级或降级 Mole。这是接口版本检查，不是对运行中文件变化的事务锁。

## 取消与进程保护

任务栏提供取消。任务运行中退出应用会先询问是否取消并退出；**取消不能撤回已经完成的步骤**，即使结果标为取消，也可能已有文件或设置发生变化。

`MoleBridge` 使用参数数组直接启动包内的 `MoleGuardian`，不拼接 shell 命令，并清除 `MOLE_*` 等继承环境干扰。stdout / stderr 分别保留，合计最多 16 MiB；超量或超时会请求取消。图形界面另外限制可显示的输出量。普通 Mole 操作沿用其授权流程；Homebrew 必须提权时，固定包内 `MacCareAskpass` 使用独立原生安全输入框，仅把密码经 sudo 私有管道送交验证，主程序不接触、不保存、不记录密码。调用前验证应用和 helper 签名；不接受自定义 ASKPASS 路径。

Mole 的卸载确认存在把 stdin EOF 当作确认的情况，因此 guardian 始终持有内层输入写端。取消、超时、外层输入结束或父应用死亡时，先对本次独立进程组发送 TERM，给予至少 3 秒宽限，再 KILL 并回收主子进程，最后才关闭输入。正常主进程退出也会清理原组残留；用未回收的子进程身份避免向复用的进程组编号发信号。

该保护覆盖本次专属进程组。主动通过 `setsid` / `setpgid` 脱离的后代，以及 guardian 自身遭 SIGKILL 等不可捕获终止，不在完整回收保证内；不能据此声称任意后台任务都已停止。

## Codex 监测口径与隐私

这是诊断记录，**不是内存上限，也不保证防止 Codex 崩溃或重启**。监测不会冻结内存、暂停任务、kill / restart / SIGSTOP Codex，也不会修改 Codex 或 Docker 配置。系统压力为警告 / 严重，或完整进程总量 ≥ 8 GiB，连续 3 次后仅提示减少并行任务。

- 从 `/Applications/ChatGPT.app`、`/Applications/Codex.app`、`/Codex.app` 的 bundle 元数据核对 `com.openai.codex` 主可执行文件，使用 libproc / `proc_pid_rusage` 的 `phys_footprint` 采样其当前后代；监测不为每次采样启动 `ps`。
- 读取 footprint 前后检查 PID 的 BSD 启动时间，采样末尾再核对主程序身份。读取失败不按 0 处理；不完整样本不显示成完整总量。瞬时 footprint 之和受共享与统计口径影响，不等于活动监视器的整机已用内存。
- 主程序与 Renderer 的 PID / 启动时间集合分别记录变化，只表示“启动 / 退出，原因未判定”，不能自动判定崩溃或 OOM。已被 launchd 收养、无法关联到当前树的孤立进程不在统计内；按名称和祖先关系推断的进程分类也不等于逻辑任务计数。
- 内核压力来自 `kern.memorystatus_vm_pressure_level`：1 / 2 / 4 对应正常 / 警告 / 严重，其他值或读取失败为未知。Swap 来自 `vm.swapusage`。受限环境读取失败时，不能把结果当成真实 0。
- 监测日志写在本机 `~/Library/Logs/CodexMemoryWatch`，目录权限 0700、文件 0600；按本地日期轮转，最近 7 个日历日、总计不超过 20 MiB。单日超限会保留该日最近一小段再继续写入，最近 60 次趋势另保存在内存中。
- 监测日志仅保存时间、PID、进程基名、计数和内存 / 压力指标，不保存完整路径、argv、环境、对话或文件正文。Mole 的预览和执行输出可能包含文件路径；Mole 自身生成的清单与操作历史遵循其日志机制，不能套用上述监测日志的字段与保留限制。

没有开机自启或系统通知权限要求；退出后停止采样。本机操作历史继续写入 `~/Library/Application Support/CodexMemoryWatch/maintenance-history.json`。Lightpaw 没有网页服务器，Codex 监测本身不发网络请求；用户明确执行的 Mole 系统维护可能影响网络服务。
